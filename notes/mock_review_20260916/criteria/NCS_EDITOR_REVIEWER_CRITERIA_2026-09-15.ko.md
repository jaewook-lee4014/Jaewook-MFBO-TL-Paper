# Nature Computational Science: 에디터·전문가 리뷰 기준

조사일: 2026-09-15. 대상 저널: **Nature Computational Science(NCS)**.
용도: 저자 자신의 투고 전 모의 심사와 LLM 리뷰 지시문을 위한 근거 문서.
분야별 적용 대상: 다중 충실도 베이지안 최적화(MFBO), 전이학습(TL), 분자·재료 탐색.

이 문서는 심사 기준을 정리한 자료이며, 현재 원고에 대한 심사 결과가 아니다. 저장소의 README와 원고 도입부는 분야 확인에만 사용했다.

## 1. 핵심 구분

다음은 공개 자료를 종합한 실무적 해석이다.

- **초기 에디터 평가:** 이 연구의 기여와 독자 가치가 NCS에서 외부 심사를 진행할 만큼 설득력 있게 제시되는가?
- **전문가 심사:** 그 기여가 정확한 방법, 공정한 비교, 충분한 증거로 성립하며, 다른 연구자가 사용할 수 있는가?
- **심사 후 에디터 판단:** 남은 쟁점이 핵심 결론을 무너뜨리는지, 수정으로 해결되는지, 해결 후에도 저널에 맞는 기여가 남는지를 판단한다.

두 역할은 중요성·신규성·검증을 모두 본다. 역할을 나누는 이유는 평가의 초점과 판단 시점이 다르기 때문이다. NCS의 편집 결정은 전임 전문 에디터가 담당한다. [NCS Journal Information](https://www.nature.com/natcomputsci/journal-information)

Nature Portfolio는 심사 후 결정을 리뷰어의 찬반 수나 점수 평균으로 내리지 않는다고 설명한다. 따라서 아래 항목을 합산해 ‘합격 점수’를 만드는 것은 적절하지 않다. [Peer Review, The review process](https://www.nature.com/nature-portfolio/editorial-policies/peer-review)

E1–E8은 LLM에서 참조하기 위한 식별자다. 저널의 공식 문항 번호가 아니다.

| E2 | 기여의 성격 | 새 방법, 기존 방법의 새로운 활용, 체계적 분석 중 무엇을 제공하는가? | [Formats for reporting primary research](https://www.nature.com/articles/s43588-023-00588-y) |
| E3 | 문제의 중요성 | 왜 풀어야 할 문제이며 기존 방법으로 무엇이 해결되지 않는가? | [To review or not to review](https://www.nature.com/articles/s43588-021-00068-1) |

| E8 | 검토 가능한 연구 자료 | 방법·데이터·코드가 연구를 평가할 수 있을 만큼 갖춰져 있는가? | [Cracking the code review process](https://www.nature.com/articles/s43588-022-00261-w) |

2021년 사설은 기존 ML 알고리즘을 그대로 사용하는 단순 적용이 대체로 범위 밖이라고 설명한다. 또한 실제 데이터와 가장 관련 있는 기존 연구에 대한 비교를 강조한다. 이것을 ‘모든 논문이 완전히 새로운 알고리즘을 발명해야 한다’는 뜻으로 확장해서는 안 된다. 이후 발표된 형식별 설명도 함께 적용해야 한다. [To review or not to review](https://www.nature.com/articles/s43588-021-00068-1)

### Article과 Analysis의 구분

| 형식 | NCS가 설명하는 기여의 중심 |
|---|---|
| Article | 개념적으로 새로운 계산적 발전과 충분한 검증. 기존 방법을 새로운 방식으로 활용하는 경우도 포함한다. |
| Analysis | 중요한 방법·도구의 체계적 성능 비교를 통해 실용적이며 주목할 만한 결론을 도출한다. 일반적으로 새 방법 개발이 중심은 아니다. |
| Resource | 연구 공동체에 유용한 도구·프레임워크 등 자원을 제공하고 실제 사례로 활용성과 적용 범위를 보인다. |

형식에 관계없이 기본 평가 기준과 코드 관련 기준은 적용되며, 편집진은 적절한 형식 선택을 저자와 논의할 수 있다고 설명한다. [Formats for reporting primary research](https://www.nature.com/articles/s43588-023-00588-y)

**MFBO/TL 적용 제안:** 벤치마크 논문이라면 모델의 수보다 비교에서 얻은 새 지식이 중요하다. 예를 들어 어떤 관찰 가능한 조건에서 어떤 모델을 선택해야 하는지, 기존 설명이 어느 조건에서 실패하는지, 선택 규칙이 별도 문제에서도 유지되는지를 확인한다. 단순 순위표만 남는다면 독자 가치가 약해질 수 있다. 이는 원고를 평가할 질문이며 현재 원고에 대한 판정은 아니다.

### 실제 데이터와 새로운 실험의 구분

NCS는 연구 주제와 주장에 맞는 검증을 요구한다. 기존 실험 데이터가 유효한 대안이 될 수 있고, 새 물질의 성능이나 발견을 강하게 주장할수록 합성·특성 평가 등 직접 검증이 필요할 수 있다. 사설 자체도 이를 고정된 규칙이 아닌 분야별·사례별 안내라고 설명한다. [Experimental validation, anyone?](https://www.nature.com/articles/s43588-023-00462-x)

**적용 제안:** ‘기존 분자·재료 데이터에서 수행한 순차 최적화’와 ‘실험실에서 실제 신규 발견을 가속했다’는 서로 다른 검증 범위를 갖는다. 모의 심사에서는 원고가 실제로 한 주장을 기준으로 필요한 증거를 정한다.

## 3. 전문가 리뷰어가 보는 공통 기준

R1–R8 역시 이 문서의 분류다.

| ID | 평가 축 | 리뷰어가 확인할 내용 |
|---|---|---|
| R1 | 기술적 타당성 | 수학, 알고리즘, 구현 및 핵심 가정의 정확성 |
| R2 | 방법론적 신규성과 맥락 | 가장 가까운 연구와의 차이, 정확한 인용, 기여의 중요성 |
| R3 | 주장과 증거의 대응 | 핵심 결론을 데이터가 지지하는지, 해석이 과도하지 않은지 |
| R4 | 데이터와 비교 설계 | 데이터의 품질, 적절한 비교 대상과 평가 방식 |
| R5 | 통계와 불확실성 | 반복 단위, 오차막대, 통계 분석과 불확실성 해석 |
| R6 | 실제 효용과 한계 | 사용 조건, 실패 조건, 일반화 범위 |
| R7 | 재현과 재사용 | 코드·데이터·환경으로 결과 확인 및 다른 문제 적용이 가능한지 |
| R8 | 설명의 명료성 | 방법·그림·결론을 독자가 정확히 이해할 수 있는지 |

NCS는 서로 다른 전문성을 가진 리뷰어를 통해 논문의 여러 측면을 평가하며, 리뷰어에게 자신의 평가 가능 범위도 밝히도록 요청한다. 문법 교정보다 기술적 타당성, 기여, 증거와 이해 가능성에 무게를 둔다. [Acing the peer review process](https://www.nature.com/articles/s43588-022-00227-y)

공통 정책은 SI를 포함한 데이터 검토, 통계·오차막대의 적절성, 근거를 갖춘 의견을 요청한다. [Nature Portfolio Peer Review, Writing the review](https://www.nature.com/nature-portfolio/editorial-policies/peer-review)

### 2026년 편집진이 정리한 반복적인 심사 지적

2026년 4월 사설은 실제로 자주 받는 리뷰 의견을 네 범주로 정리한다.

| 범주 | 반복되는 쟁점의 요약 |
|---|---|
| 비교·검증 | 중요한 최신 비교 방법 누락, 부적절한 지표, 비교 설정·제외 사유 부족 |
| 연구 맥락 | 기존 연구와의 차이 불명확, 과장된 신규성, 선택적 결과 보고, 통계 부족 |
| 실용성 | 한계 설명 부족, 현실적 문제와 확장성 검증 부족, 데이터 누출 |
| 명료성 | 재현에 필요한 설정 누락, 설명이 불충분한 그림, 모호하거나 과장된 주장 |

이 사설은 비교가 부족해도 다른 강점 때문에 외부 심사로 진행하는 경우가 있음을 밝힌다. 따라서 이 항목들은 기계적인 탈락 조건이 아니다. [What reviewers request the most](https://www.nature.com/articles/s43588-026-00989-9)

### 코드·ML 보고에 대한 별도 점검

NCS의 코드 심사 안내는 **완전성, 결과의 재현성, 다른 연구자의 재사용 가능성**을 다룬다. 설치·실행 설명, 실험에 대응하는 입력 자료, 제한된 자료의 대안과 사유도 중요하다. 리뷰어의 자원 제약을 인정하므로 모든 실험의 재실행이 항상 가능한 것은 아니다. [Cracking the code review process](https://www.nature.com/articles/s43588-022-00261-w)

ML 보고 사설은 데이터 수집·정제·편향, 학습/검증/시험 분할, 모델 선택과 ablation, 학습 시간, 난수, 하드웨어·소프트웨어 및 모델 공유를 강조한다. [Moving towards reproducible machine learning](https://www.nature.com/articles/s43588-021-00152-6)

**적용 제안:** LLM은 ‘코드가 링크되어 있음’, ‘코드를 읽었음’, ‘일부 실행함’, ‘주요 결과를 재현함’을 별도로 기록해야 한다. 파일을 읽는 작업만으로 재현성을 확인했다고 판단하지 않는다.

## 5. MFBO·전이학습 원고를 위한 전문가 질문

아래 F1–F15는 **분야 문헌과 위 기준을 바탕으로 구성한 적용 제안**이다. NCS의 공식 체크리스트가 아니며, 모든 항목에 새 실험이 필요한 것은 아니다.

화학 ML의 분야 권고는 단순한 baseline과 강한 기존 방법의 비교, 목적에 맞는 검증 분할 및 반복 학습 민감도를 강조한다. [Artrith et al., Best practices in machine learning for chemistry](https://www.nature.com/articles/s41557-021-00716-z)

### F1. 주장하는 연구 질문과 비교 방식

- ‘전이 메커니즘 자체의 효과’라면 backbone, 정보 접근, 초기 설계, 학습 조건 등 혼동 요인을 통제했는가?
- ‘실제로 가장 좋은 방법’이라면 각 비교 방법에 합리적인 튜닝과 적절한 사용 조건을 제공했는가?
- 통제 실험과 각 방법의 최선 성능 비교는 다른 질문이다. 하나의 비교가 둘을 모두 입증한다고 가정하지 않는다.
- NN과 GP에 동일한 파라미터 수를 강제하는 것이 공정성의 필요조건은 아니다. 통제해야 할 자원이 무엇인지 연구 질문으로 설명한다.

### F2. 전이학습의 이득과 모델 표현력의 이득

- HF-only 모델, LF를 사용하지 않은 동일 계열 모델, 단순 LF 기반 screening과 비교하면 무엇을 구분할 수 있는가?
- LF 활용이 유익한 조건과 오히려 해로운 조건을 평가했는가?
- LF 없이도 같은 개선이 나온다면, ‘전이의 효과’라는 설명을 어느 수준까지 유지할 수 있는가?
- 이런 비교의 필요성은 주장에 달려 있다. 방법의 성능 보고와 작동 원인 설명에는 다른 증거가 필요하다.

### F3. 순차 탐색에서 허용된 정보

- 각 단계에서 모델·획득함수·튜닝 과정이 접근하는 LF/HF 라벨이 명확한가?
- 전체 HF 라벨로 계산한 정규화·특징 선택·임계값·모델 선택 결과가 탐색 과정에 들어가지 않는가?
- 전체 풀의 최적값을 사후 성능 계산에만 사용하는 것과, 그 값을 알고 행동을 선택하는 것을 구분했는가?
- 유한한 후보 집합의 특징을 모두 아는 설정은 가능하다. 이것을 미관측 라벨 접근과 혼동하지 않는다.

### F4. 비용과 fidelity 선택의 공정성

- LF·HF 조회, 초기 데이터, 사전학습 데이터의 비용을 무엇으로 정의했는가?
- 이미 존재하는 LF 데이터의 재사용과 새로 LF 데이터를 취득하는 경우를 구분했는가?
- 고정 fidelity 일정의 비교라면 결과가 대리모델 비교인지, 비용에 따라 fidelity를 선택하는 전체 MFBO 정책 비교인지 명확한가?
- 실험 횟수, 환산 취득 비용, 알고리즘 계산 시간은 서로 다른 평가축으로 보고하는가?

### F5. 비교 대상의 충분성과 설정

- 가장 가까운 MFBO 방법과 해당 입력 표현에 적합한 강한 baseline을 포함했는가?
- Random search, HF-only BO, 단순 LF screening은 각각 어떤 주장을 점검하는가?
- 커널, 특징 처리, 최적화 restarts, sparse approximation, 학습 종료 조건 등이 비교 방법을 불필요하게 약화시키지 않는가?
- 추가할 방법은 ‘누락됨’만으로 요구하지 않는다. 관련 논문과 현재 결론을 바꿀 수 있는 이유를 함께 제시한다.

### F6. 여러 모델 중 최고값의 선택 효과

- 서로 다른 크기의 모델 집합에서 best-of-family를 비교하는가?
- 문제별로 결과를 본 뒤 고른 승자는 실제 사용 전에 선택할 수 있는가?
- 사전에 정한 대표 모델, 검증 데이터 기반 선택, 집합 전체의 성능 분포를 구분하는가?
- 관찰된 평균 최고값을 모든 모델의 우월성이나 새로운 문제에서의 선택 가능성으로 확대하지 않는가?

### F7. 최적화 목적에 맞는 지표

- 예측 오차와 실제 최적화 성공을 별도로 측정하는가?
- best-observed HF, simple regret, 목표 도달 비용, 경로 전체의 성능 중 주장에 맞는 지표를 사용하는가?
- 정규화·적분 구간·예산·최적값의 정의와 미도달 run의 처리가 명확한가?
- 0에 가까운 regret를 나눈 배율, 일부 시점만 선택한 차이, 모든 방법이 포화된 결과를 과대해석하지 않는가?

### F8. 반복·통계·실패 run

- 같은 초기 설계를 공유하는 비교라면 paired 분석이 적절한지 검토했는가?
- seed 반복과 독립적인 과제 반복을 구분하는가? 같은 원천 데이터에서 만든 여러 변형을 독립 문제처럼 세지 않는가?
- 오차막대가 SD, SE, CI 중 무엇인지 명시했는가? 효과 크기와 변동성을 같이 판단할 수 있는가?
- 실패·누락 run, 조기 종료, 모델별 다른 표본 수를 설명하고 결과에 미치는 영향을 점검했는가?
- 평균이 비슷하거나 유의한 차이가 없다는 것만으로 통계적 동등성 또는 비열등성이 입증되지는 않는다.

### F9. 결과의 설명과 원인 주장

- ‘표현학습 때문에 개선된다’는 결론에서 용량·학습량·획득함수·입력 표현의 영향을 분리했는가?
- 상관, 예측 관계, 제어된 실험에서의 효과를 서로 구분하는가?
- near-optimal ranking이 중요하다는 설명에 top-k 영역 정의나 난이도가 영향을 주지 않는가?
- 새 실험 없이도 표현을 ‘일치한다/시사한다’로 제한하면 증거와 일치하는지 먼저 검토한다.

### F10. 불확실성과 획득함수

- LF에서 측정한 calibration과 HF 의사결정에 쓰는 불확실성을 구분했는가?
- 획득함수가 모델별로 다른 경우 대리모델만의 효과라고 결론 내릴 수 있는가?
- EI, Thompson sampling 등 이름이 같아도 fidelity 선택 위치·후보 집합·최적화 구현이 다르지 않은가?
- 특정 실험에서 uncertainty-driven policy의 이득이 작았다는 결과를 BO 전반에서 불확실성이 불필요하다는 주장으로 확대하지 않는가?

### F11. 데이터의 독립성과 일반화 범위

- 여러 데이터셋이 실제로 다른 화학·재료 문제, 표현, LF/HF 관계를 담고 있는가?
- 기존 후보 풀 내부 탐색 성능과 새로운 scaffold·재료군·시간 구간으로의 일반화를 구분하는가?
- 주장하는 적용 범위에 맞는 외부 검증인가? 풀 내부 탐색만 주장한다면 무관한 OOD 시험을 자동으로 필수화하지 않는다.
- 순수 합성 함수, 시뮬레이션 기반 과학 데이터, 실험 측정 데이터의 성격을 각각 설명하는가?

### F12. 실제로 사용할 수 있는 선택 규칙

- 어떤 모델·LF 소스를 고를지 결정하는 진단값을 탐색 전에 또는 제한된 초기 데이터로 추정할 수 있는가?
- 진단값을 얻는 데 필요한 HF 측정의 비용과 불확실성이 반영되는가?
- 사후의 전체 데이터 분석이라면 실시간 선택 알고리즘으로 오해되지 않도록 설명하는가?
- 선택 기준이 별도의 문제에서도 유효한지는 그 기준의 일반성 주장에 맞춰 평가한다.

### F13. 확장성과 속도

- FLOPs, 학습 시간, 예측·획득함수 비용, 전체 실행 시간, 메모리를 구분하는가?
- 반복 재학습·추론·초기화·튜닝 비용과 하드웨어·정밀도·병렬화 조건을 명시하는가?
- 이론적 복잡도와 제한된 구간에서 측정한 경험적 증가율을 구분하는가?
- surrogate 연산량의 감소를 실험실 전체 소요 시간의 같은 배율 감소로 해석하지 않는가?

### F14. 원고–실행–공개 코드의 일치

- 각 그림·수치가 해당 데이터 버전, 설정, seed, raw output, 분석 코드에 연결되는가?
- 수정 전·후 실험이 섞이지 않으며, 공개 또는 심사용 snapshot이 현재 원고와 일치하는가?
- README로 설치와 대표 실행을 할 수 있으며 필요한 데이터·경로·의존성이 제공되는가?
- 실행 자원이 부족하다면 검토한 범위와 남은 검증을 구분한다. 미실행은 곧바로 재현 실패를 뜻하지 않는다.

### F15. 기여의 경계와 정직한 설명

- 제목·초록·결론의 최상위 주장이 전체 결과의 범위와 일치하는가?
- GP가 우세한 조건, 전이가 실패하는 조건, 데이터 편향 등 결론의 경계를 제시하는가?
- 두 fidelity·고정 일정·유한 후보 풀의 결과라면 그 범위를 명확히 하는가?
- ‘최초’, ‘보편적’, ‘원인’, ‘실험실 가속’처럼 강한 표현마다 필요한 별도 증거가 있는가?

## 6. LLM 평가를 위한 판정 규칙

이 절은 공식 심사 등급이 아니라 **모의 심사를 위한 설계 제안**이다.

### 증거 상태를 먼저 기록

| 상태 | 의미 |
|---|---|
| 확인됨 | 제공 자료 또는 실행 결과에서 직접 확인했다. |
| 부분 지지 | 일부 증거는 있으나 주장 전체를 지지하지 않는다. |
| 미보고 | 확인한 제출 자료에서 필요한 설명을 찾지 못했다. |
| 접근·전문성 한계 | 자료나 실행 환경이 없거나 평가 능력의 범위를 넘는다. |
| 상충함 | 서로 다른 위치의 설명·수치·결과가 충돌한다. |

### 그다음 판단에 미치는 영향 분류

| 분류 | 판정 조건 |
|---|---|
| 핵심 타당성 문제 | 핵심 결론을 무효화하는 오류·누출·비교 왜곡 등이 구체적 근거로 확인됨 |
| 주요 수정 | 결론이나 적용 범위를 판단하려면 중요한 설명·재분석·검증이 필요함 |
| 경미 수정 | 결론을 바꾸지 않는 명료화·표기·보조 설명 문제 |
| 선택적 확장 | 현재 주장에 필수는 아니지만 후속 가치가 있는 연구 |

‘확인하지 못했다’를 ‘잘못되었다’로 바꾸지 않는다. 반대로 과학적 오류가 없다는 사실만으로 NCS 적합성이 확보되는 것도 아니다. 타당성 문제와 편집적 중요성 문제를 별도 논거로 작성한다.

### 좋은 지적의 형식

> 위치와 대상 주장 → 관찰된 근거 → 어떤 결론이 왜 영향을 받는지 → 최소한의 해결 방법 → 해결됐다고 볼 조건.

예시(가상의 원고):

> 초록에서 모든 화학 문제의 우월성을 주장하지만 Figure X는 문제별 사후 선택한 최고 모델의 평균만 보여준다. 이 결과로는 사전에 선택 가능한 하나의 방법의 우월성을 판단하기 어렵다. 우선 주장을 관찰된 집합 비교로 한정하거나, 독립적인 선택 규칙을 평가해야 한다. 후자를 유지하려면 선택과 최종 평가의 데이터를 분리하고 그 결과를 보고하는 것이 해결 조건이다.

예시의 Figure X와 문제는 실제 원고에서 발견한 것이 아니다.

## 7. LLM에서 사용하는 순서

1. 이 문서를 기준 자료로 제공한다.
2. 평가할 최종 원고와 SI의 버전·파일명을 지정한다. 코드가 있다면 해당 원고에 대응하는 버전도 지정한다.
3. 함께 제공된 `NCS_LLM_REVIEW_PROMPTS.ko.md`에서 공통 지시문과 원하는 역할 지시문을 사용한다.
4. 초기 에디터와 전문가 리뷰를 각각 작성하게 한 뒤, 심사 후 에디터 지시문으로 쟁점을 종합한다.
5. 독립적 시각이 필요하면 별도 대화에서 역할별로 평가하고, 종합 단계에서만 보고서를 모은다. 이는 권장 사용 방식이며 실제 NCS 심사위원 구성을 예측한 것은 아니다.

기존 내부 리뷰나 저자의 방어 논리를 처음부터 입력하면 결론이 그 문서에 끌릴 수 있다. 독립적인 초안 평가 후 참고자료로 추가하는 방법을 권장한다. LLM이 문헌 검색을 하지 못한다면 신규성 판단의 확인 범위를 명시하게 한다.
